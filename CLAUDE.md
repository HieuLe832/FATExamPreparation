# FAT study guide

## Goal

One web app with one job: teach the user just enough FAT to solve `Baitap_HTTT.pdf`, using the lecture
`Bai02_Quan_ly_tap_tin.pdf`. Don't teach the whole course. Every section must serve a question in the
exercise (bài 1: MBR partitions; bài 2a–e: a FAT32 volume read from hex dumps).

## Stack

- Frontend: React 18 + Vite in `client/`.
- Host: ASP.NET Core 8 (C#) in `server/`. It serves the built client from `server/wwwroot` and falls back to
  `index.html` for SPA routes.
- PostgreSQL or a cache: don't add one yourself. Ask the user, who will create a Supabase database or an
  Upstash Redis. The guide needs neither today.
- Decide everything else yourself without asking.

## Layout

| Path | What |
| --- | --- |
| `client/src/fat/dumps.js` | Hex dumps transcribed from the exercise screenshots |
| `client/src/fat/annotate.js` | Pure decoders: MBR, boot sector, FAT32 elements, directory entries |
| `client/src/fat/annotate.test.js` | Pins the dumps to the answers shown on the page |
| `client/src/components/` | `HexDump` (clickable dump), `Calculators`, shared `Study` blocks |
| `client/src/sections/` | Lesson content, in page order |
| `client/public/slides/` | Slide crops (generated by `scripts/crop_slides.py`) |
| `client/public/de/` | Original hex screenshots extracted from the exercise PDF |
| `server/` | ASP.NET host |

## Commands

```bash
cd client && npm install          # once
cd client && npm run dev          # live-reload dev server
cd client && npm test             # decoder tests (node:test)
cd client && npm run build        # outputs to server/wwwroot
dotnet run --project server       # http://localhost:5080 (builds the client first if wwwroot is empty)
```

Regenerate slide crops:

```bash
pdftoppm -r 150 -png Bai02_Quan_ly_tap_tin.pdf /tmp/slides/s
python3 scripts/crop_slides.py /tmp/slides client/public/slides
```

## Conventions

- UI language is Vietnamese with full diacritics.
- Cite slides by showing the cropped slide image inline (`<Slide n={..} />`). Never write "see slide N":
  the user doesn't want to switch tabs. Captions name the topic, not the slide number.
- Each lesson goes: slide crop → how to do it → "Tự làm" prompt → collapsed `<Answer>`. Answers stay
  collapsed so the user tries first.
- Commit messages: `type: summary` (e.g. `feat: add FAT chain lesson`, `fix: correct cluster 11 sector`).

## Known pitfalls

- **The `supabase password` file in the repo root is a secret.** It is gitignored; never read it into code,
  commit it, or paste it anywhere.
- **Transcribed hex must match the screenshots.** If you edit `dumps.js`, compare with `client/public/de/*.png`
  and run `npm test`; the tests encode the answers (partition sizes, 38/813/1664 layout, FAT chains, tree).
- **Answer text is hand-written in `sections/`**, separately from the decoders. A change to a dump or
  formula means updating both the prose answers and the tests.
- **`calc` and `ent` strings from `annotate.js` render as HTML.** Any text that comes from dump bytes
  must go through `esc()`.
- **`pkill -f <name>` can match the shell running it** and kill your own command. Stop the dev server by
  PID or with Ctrl+C instead.
- **Headless Firefox hangs in this environment.** To check rendering without a browser, server-render with
  `npx vite build --ssr src/App.jsx` and `react-dom/server`.
- **Pick crop boxes on the 100 dpi render**; `crop_slides.py` scales them ×1.5 for the 150 dpi images. Crop
  below the "fit@hcmus" logo, and keep the slide title in the crop so it explains itself.
- FAT-specific traps for the user (little-endian, cluster numbering from 2, no S_RDET on FAT32, FAT2 copy,
  E5/LFN entries, and so on) are listed on the page under "Lỗi hay gặp" (`sections/Reference.jsx`). Keep
  that list in sync when you add lessons.
